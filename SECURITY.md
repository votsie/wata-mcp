# Политика безопасности

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный issue** для сообщений об уязвимостях —
это раскроет проблему всем до того, как появится исправление.

Используйте [GitHub Security Advisories](https://github.com/votsie/wata-mcp/security/advisories/new)
этого репозитория, чтобы сообщить о проблеме приватно, с шагами воспроизведения
и потенциальным воздействием.

## Что делает этот проект с секретами

Сервер не хранит и не передаёт секреты никуда, кроме `api.wata.pro` и
`merchant.wata.pro`. Учётные данные хранятся только локально, в
`~/.wata-mcp/`, с правами `600` на файлы и `700` на каталог. Аудит-лог
изменяющих операций (`~/.wata-mcp/audit.log`) маскирует чувствительные поля —
пароли, коды подтверждения, cookie, номера карт — перед записью на диск.

## Предупреждение пользователям

Не передавайте пароль и код подтверждения (2FA) как аргументы инструментов —
они попадут в историю диалога вашего AI-клиента. Используйте переменные
окружения `WATA_EMAIL` / `WATA_PASSWORD` либо интерактивный вход командой
`wata-mcp login`.

## Необратимые денежные операции

Часть инструментов выполняет необратимые операции с деньгами. Вывод средств —
трёхшаговый и требует кода подтверждения. Возвраты платежей требуют явной
передачи `confirm: true` — без этого операция не выполняется.

## Ограничение на Windows

На Windows права `600`/`700` не действуют так же, как в POSIX — NTFS не
поддерживает эту модель напрямую. Защита секретов держится на правах профиля
пользователя ОС. Это честное ограничение, а не гарантия: не запускайте сервер
из общих или административных учётных записей Windows.

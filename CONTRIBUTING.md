# Контрибьютинг

## Как запустить проект

```bash
npm install
npm run build
npm test
node dist/cli.js doctor
```

`doctor` проверяет окружение (сессию, переменные, доступность API) без
выполнения изменяющих операций.

## Структура проекта

`src/core` — транспорт и сессия: HTTP-клиент к api.wata.pro и merchant.wata.pro,
cookie jar, антиDDoS-паузы, аудит-лог, пути. `src/tools` — MCP-инструменты по
доменам (эквайринг, платежи, кошелёк, терминалы, вебхуки, цифровые товары).

`src/install` — автоустановка агентских скиллов в клиенты. `skills/` — сами
скиллы: инструкции для агента по работе с разделами wata.pro. `docs/` — карты
API (`api-map.md`, `public-api.md`) с описанием используемых эндпоинтов.

## Главное правило

**Никогда не коммитьте реальные учётные данные, идентификаторы терминалов,
транзакций и куки.** В тестах используйте выдуманные значения: UUID из нулей
(`00000000-0000-0000-0000-000000000000`), домены `example.com`, IP из
диапазона `203.0.113.0/24`. CI сканирует секреты по всей истории коммитов —
удаление в следующем коммите не спасает.

## Что проверяет CI

- `npm run typecheck`;
- `npm test`;
- скан утечки секретов по рабочему дереву и всей истории коммитов.

## Как добавить новый инструмент

1. Файл в `src/tools/` (или дополните существующий домен).
2. Зарегистрируйте инструмент в `src/server.ts`.
3. Опишите его для модели: не только что делает, но и где легко ошибиться
   (необратимость операции, обязательный `confirm: true`, единицы сумм,
   различия между терминалами/окружениями).
4. При новом эндпоинте обновите `docs/api-map.md` или `docs/public-api.md`.

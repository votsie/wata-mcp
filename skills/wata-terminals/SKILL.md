# Терминалы WATA

## Обзор

- `wata_terminals_list` — все терминалы с оборотом и выручкой за период
- `wata_terminal_get` — карточка терминала: `webHookUrl`, `successPageUrl`, разрешённые домены
- `wata_terminals_finance` — балансы терминалов и готовность к выплате

Различайте два идентификатора: `id` используется в запросах кабинета,
`publicId` — в публичном API и в digital goods.

## API-токены эквайринга

```
wata_terminal_api_tokens_list   { terminalId }
wata_terminal_api_token_create  { terminalId, payload }
wata_terminal_api_token_revoke  { terminalId, tokenId }
```

Значение токена возвращается один раз при создании — сохраните его сразу,
повторно сервер его не покажет. Токен действует только в рамках своего терминала.

## Ставки

- `wata_terminal_rates` — комиссии WATA по методам оплаты
- `wata_terminal_payer_rates_set` — какая часть комиссии перекладывается на плательщика

Перед изменением обязательно посмотрите текущие значения через `wata_terminal_rates`
и меняйте только те поля, которые действительно нужно изменить.

## Вебхуки и настройки терминала

Текущие значения видны в `wata_terminal_get`, меняются через `wata_terminal_update`:

- `webhookUrl` — адрес приёма уведомлений
- `successPageUrl`, `failPageUrl` — куда возвращать плательщика
- `sendPayWebhook` — постоплатные уведомления
- `sendPayWebhookOnDecline` — слать и по отклонённым платежам
- `sendPrePayWebhook` — предоплатные уведомления
- `sendRefundWebhook` — уведомления о возвратах

Передавайте только изменяемые поля: инструмент шлёт `PATCH`, остальные настройки
остаются как были.

**Осторожно с предоплатным вебхуком.** Он приходит до обращения в банк, и WATA ждёт
ответа **10 секунд**. Если ваш сервер не ответит вовремя, транзакция будет отклонена
без обращения в банк — то есть включение этого флага при неготовом обработчике
останавливает приём платежей. Постоплатный и возвратный ведут себя мягче: WATA
повторяет доставку с нарастающим интервалом до 32 часов.

Если уведомление не дошло, повторную доставку запускает
`wata_transaction_resend_webhook` — это чаще правильное решение, чем ручная правка
статуса заказа. Проверка подписи разобрана в скилле `wata-webhooks`.

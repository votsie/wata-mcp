# Цифровые товары WATA

База: `https://dg-api.wata.pro/api`. Авторизация — тот же Bearer JWT, что и в эквайринге.

## Два способа оплаты — главная развилка

У каждого направления **два разных набора эндпоинтов**, и выбирается он параметром `payment`:

- **`acquiring`** — заказ оплачивает конечный покупатель (в ответе приходит ссылка на оплату)
- **`deposit`** — заказ списывается с депозитного баланса мерчанта

Перепутать их легко, поэтому во всех инструментах `payment` — обязательный параметр.
Депозитный баланс смотрите через `wata_dg_deposit_balance`; это отдельный баланс,
не совпадающий с кошельком кабинета.

## Типичный порядок работы

```
1. wata_dg_catalog            { payment, kind }   — что вообще можно продать
2. wata_dg_steam_price / ...  — сколько это стоит
3. wata_dg_order_create       — создать заказ
4. wata_dg_order_get          — дождаться финального статуса
```

Никогда не считайте заказ выданным сразу после создания: оплата и выдача — разные
события, и заказ может быть оплачен, но не выдан.

## Steam

`wata_dg_steam_price` и `wata_dg_steam_order_create` работают в двух режимах:

- `by: 'netAmount'` — вы задаёте, **сколько зачислить** на Steam-аккаунт
- `by: 'price'` — вы задаёте, **сколько платит** покупатель

Разница существенная: комиссия и курс делают эти суммы разными. Уточняйте у заказчика,
какая именно сумма имелась в виду.

## Telegram Stars

Особенность: заказ может попасть в статус **`Review`** — тогда он ждёт вашего решения:

```
wata_dg_stars_order_confirm   { id }   — подтвердить
wata_dg_stars_order_reject    { id }   — отклонить
```

Заказ в `Review` не выполняется сам по себе. Если звёзды «не пришли» — сначала
проверьте статус: скорее всего, заказ ждёт подтверждения.

## Top-Up и ваучеры

`wata_dg_catalog` с `kind: 'topup'` даёт игры и внутриигровые позиции,
с `kind: 'vouchers'` — сервисы и номиналы ваучеров.

Для ваучеров с оплатой `acquiring` **коды возвращаются в статусе заказа**
(`wata_dg_order_get`) — отдельного эндпоинта выдачи кодов нет.

## Статусы заказов

У депозитных заказов один общий эндпоинт статуса для всех направлений
(`/v1/deposit/order/{orderId}`), у acquiring — свой на каждое направление.
Инструмент `wata_dg_order_get` выбирает правильный сам, если передать `payment` и `kind`.

## Кабинет

Обзор всех заказов цифровых товаров есть и в кабинете:
`wata_digital_goods_orders`, `wata_digital_goods_order_statuses`,
`wata_digital_goods_order_get` (последний требует `publicId` терминала, а не внутренний `id`).

Полная карта эндпоинтов — в `docs/public-api.md`.

# Публичный API эквайринга WATA

База: `https://api.wata.pro/api/h2h` (песочница — `https://api-sandbox.wata.pro/api/h2h`,
переключается переменной `WATA_ENV=sandbox`).

## Модель доступа — читать первым делом

| | Кабинет (сессия) | Публичный API (JWT) |
|---|---|---|
| Область | весь аккаунт | **один терминал** |
| Авторизация | `auth_cookie` + antiforgery | `Authorization: Bearer <JWT>` |
| Назначение | управление и отчётность | приём платежей в проде |

Терминал в запросах **не указывается** — он определяется самим токеном. Если платёж ушёл
«не на тот терминал», причина всегда одна: использован токен другого терминала.

## Получение токена

```
wata_terminal_api_tokens_list   { terminalId }
wata_terminal_api_token_create  { terminalId, name, expirationMonths }
```

Значение показывается **один раз** — сразу сохраните его в `WATA_ACQ_TOKEN`.
На терминал допускается 1–5 токенов, срок 1–12 месяцев. Токен работает только
с согласованных с WATA IP-адресов — при отказе `401/403` с корректным токеном
проверяйте в первую очередь IP.

## Платёжные ссылки

`wata_acq_link_create` — основной способ принять оплату.

Ограничения, о которые чаще всего спотыкаются:
- сумма от 10 RUB (1 USD/EUR) до 999999.99
- срок жизни от 10 минут до 30 дней, по умолчанию 3 дня
- подсказок произвольной суммы максимум 6, и каждая не меньше `amount`

Поиск — `wata_acq_links_find` (постраничная пагинация), карточка — `wata_acq_link_get`
(только он возвращает блок `digitalGood`).

Закрыть ссылку можно инструментом кабинета `wata_link_close`.

### Подписки

Передайте в `wata_acq_link_create` объект `subscription` — ссылка станет регулярным
списанием: `period`, `interval` (Test/Week/Month), `maxPeriods`, `amount`.
Управление созданными подписками — в скилле `wata-links`.

## Транзакции и возвраты

`wata_acq_transactions_find` использует **курсорную** пагинацию: для следующей страницы
передайте `cursorId` и `cursorAmount` из полей `nextCursorId` и `nextCursorAmount`.
Это отличается от поиска ссылок, где обычные skip/take.

`wata_acq_refund_create` — необратимая операция, поэтому требует явного `confirm: true`.
Кроме него нужны только `originalTransactionId` и `amount`: валюта берётся из исходной
транзакции, поля «причина» в API нет. Исходная транзакция должна быть в статусе Paid
и принадлежать тому же терминалу, что и токен.
Возврат недоступен на терминалах с продуктом «Цифровые товары + Эквайринг».

## Баланс

`wata_acq_balance` принимает **только сегодняшнюю или вчерашнюю** дату по UTC.
За любой другой период берите отчёты кабинета: `wata_finance_daily`.

## Прямая оплата (H2H)

- `wata_acq_pay_sbp` → возвращает `sbpLink`
- `wata_acq_pay_tpay` → возвращает `tPayLink`
- `wata_acq_pay_card` → требует криптограмму карты

Криптограмму **невозможно собрать на сервере**: её формирует клиентский скрипт чекаута
WATA в браузере плательщика. Если готовой криптограммы нет — используйте платёжную ссылку.
СБП и T-Pay работают только с рублями, поля валюты у них нет вовсе.

## Частые ошибки

| Симптом | Причина |
|---|---|
| `401/403` при верном токене | запрос с несогласованного IP либо токен другого окружения |
| `429` | лимит 1 GET за 30 секунд на части эндпоинтов |
| Баланс отвечает ошибкой | дата не сегодняшняя и не вчерашняя по UTC |
| Возврат отклонён | продукт терминала «Цифровые товары + Эквайринг» либо не хватает баланса |

Полная карта эндпоинтов и enum'ов — в `docs/public-api.md`.
Проверка подписи уведомлений — в скилле `wata-webhooks`.

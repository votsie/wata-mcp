# Подключение WATA MCP

## Установка

```bash
npm install && npm run build
node dist/cli.js install     # пропишет сервер в Claude Code, Codex, Antigravity
```

`install` правит только запись `wata` и сохраняет остальные настройки пользователя.
Для агента, который не обнаружен на машине, добавьте `--all`.

## Вход

Кабинет требует второй фактор — код приходит на почту, поэтому вход двухшаговый:

```bash
node dist/cli.js login --start                 # берёт WATA_EMAIL и WATA_PASSWORD
node dist/cli.js login --code 123456           # код из письма
```

Через MCP то же самое: `wata_auth_login`, затем `wata_auth_verify`.

Сессия сохраняется в `~/.wata-mcp/session.json` и живёт около 60 дней. Она
продлевается сама при каждом запросе, поэтому при регулярной работе повторный
вход обычно не требуется.

## Песочница

```bash
WATA_ENV=sandbox node dist/cli.js login
```

`WATA_ENV=sandbox` переключает **и кабинет, и публичный API** на контур песочницы
(`merchant-sandbox.wata.pro`, `api-sandbox.wata.pro`).

Важно понимать три вещи:

- у песочницы **отдельные учётные данные** — боевые логин и пароль там не работают,
  вход нужно выполнять заново;
- сессии хранятся раздельно (`session.json` и `session.sandbox.json`), поэтому
  переключение контура не рушит уже выполненный вход в другой;
- у песочницы **свой публичный ключ** для проверки подписи вебхуков — ключ, полученный
  в бою, в песочнице не подойдёт.

## Диагностика

```bash
node dist/cli.js doctor
```

Первой строкой печатает окружение (`БОЕВОЕ` или `ПЕСОЧНИЦА`) и адрес кабинета —
проверяйте это перед любой операцией с деньгами. Дальше идут наличие сессии
и доступность ключевых разделов.

## Что делать при ошибках

| Симптом | Причина | Действие |
|---|---|---|
| `Сессия WATA недействительна` | истёк `auth_cookie` | повторить вход |
| `400 без тела` | не принят antiforgery-токен | клиент чинит сам; если повторяется — повторить вход |
| Долгие ответы, отказы подряд | сработал DDoS-Guard | увеличить `WATA_MIN_REQUEST_INTERVAL_MS` |

## Важное о модели доступа

API-ключ WATA выпускается **на терминал** и не даёт доступа к кабинету целиком.
Всё, что касается кошелька, выплат, чарджбеков и настроек — только через сессию.
